🔎 五个具体缺口 → 五层机制

以前缺什么
  • 流水线是「事件发生后 → 抓新闻 → 当日复盘」，天然滞后于价格
  • 没有 L1 事件日历，选举/议息这类确定时点不会提前挂起
  • 没有 L2 领先指标，民调/赔率/提前投票/利率期货没有跟踪位
  • 没有 L4 历史类比库，苗头出现时无法调出「上次同类怎么走」
  • 没有「传导链 → 我的持仓」映射与 L5 复盘，研判落不到组合上
现在怎么补（L1 事件日历 起）
  • L1 事件日历：未来 7/30 天已知时点（政策会议、数据发布、财报、选举、关税节点）
  • L2 领先指标：民调/赔率、利率期货隐含、PMI 先行项、资金流、期权隐波、提前投票
  • L3 情景推演：每个重大事件 2–3 个情景 + 传导链 + 对 13 个标的的映射 + 预案
  • L4 历史类比：同类事件历史上怎么走，只列观察维度，具体区间数据须调权威源后填写
  • L5 触发与复盘：触发条件命中则升级为正式预警；事后回填「是否提前捕捉、判断应验与否」

为什么这类事件以前没有前瞻性
  • 既有流水线是「事件发生后 → 抓新闻 → 当日复盘」，天然滞后于价格
  • 没有 L1 事件日历，选举日这类确定时点不会提前挂起
  • 没有 L2 领先指标，民调/赔率/提前投票等结果前信号没有跟踪位
  • 没有 L4 历史类比库，无法在苗头出现时立刻调出「上次同类怎么走」
  • 没有「传导链 → 我的 13 个标的」映射，研判落不到自己的组合上
L2 领先指标
  • 关键州民调与预测市场赔率（结果前）
  • 提前投票 / 邮寄选票结构与开票节奏
  • 两党政策纲领文本与人事提名信号
  • 美元指数、美债期货与利率期权隐含波动（结果前定价）
  • 政策落地日程（国会会期、预算/拨款、监管人事）
影响传导链
  • 财政与赤字预期 → 美债供给 / 期限溢价 → 美债10Y → 全球成长股估值 → A股科技成长映射
  • 产业与监管取向（AI、半导体、出口管制） → 算力链 → 天孚通信、科创/AI 类基金
  • 贸易与关税取向 → 出口链 → 莱克电气
  • 美元 / 人民币 → 风险偏好与资金流 → 全部权益类 93.0% 仓位
  • 避险情绪 → 黄金、油价 → 盘前指引「历史风险清单」中的地缘/商品链条
L3 情景推演
情景概率传导受影响预案（观察动作）
情景 A · 统一政府（总统与两院同党）待评估政策推进阻力下降 → 财政/产业政策可预期性上升 → 视具体纲领决定对成长股是压制还是提振天孚通信、科创/AI 类基金、埃斯顿先核实纲领文本再判方向；本轮不填结论
情景 B · 分裂政府待评估立法推进受阻 → 政策不确定性延长，行政/监管手段权重上升 → 出口管制与关税仍可能单点扰动天孚通信、莱克电气重点跟踪行政口径而非立法进度
情景 C · 结果延后 / 争议待评估风险偏好短期受压、波动率抬升 → 高 Beta 成长与拥挤主线回撤弹性最大全部权益类以波动率与量能确认作为观察信号，不给操作指令
L4 历史类比维度

丰哥 11-07 以「美国民主党全面胜选 / 参众两院」为例，指出重大事件应提前有研判。本轮未核实任何选举结果、未查外部行情与新闻源做事实断言，也不把提问中的举例当作既成事实。事件雷达里对应条目状态为「待核实 · 推演模板」，confirmed=false，概率与结论字段留「待评估 / 待核实后填写」。

之所以先建模板而不是先下结论：金融红线要求关键事实标注来源与时点、禁止编造；而模板把领先指标、5 条传导链、3 个情景、历史类比维度、6 个受影响标的与触发条件全部备好，一旦结果确认或丰哥给出权威来源，可一键升级为正式预警并填结论，结构不用重做。

历史类比库里对该类事件只列观察维度（统一政府 vs 分裂政府、美股风格、利率美元、避险资产、贸易与产业取向、A股映射时滞），具体区间数值标【待调权威源】，本轮不编数。

#缺口后果
1流水线是「事件发生后 → 抓新闻 → 当日复盘」天然滞后于价格，结果出来时已反映在盘面

L1 事件日历（事件日历.md）

中国 + 全球双栏，列周期性/类型化时点：政策会议、数据发布、财报季、议息、选举、出口管制、云厂商资本开支、组合自身确定时点。每天凌晨扫一遍，未来 7/30 天确定时点挂成「前瞻」状态。不填未经官方确认的具体日期。

L2 领先指标（事件雷达.json 每条 lead_indicators）

结果前的可观测信号：民调与预测市场赔率、提前投票/开票节奏、纲领文本与人事提名、利率期货与期权隐波、PMI 先行项、板块资金流与拥挤度。指标异动即使结果未出也挂「观察中」。

L3 情景推演（事件雷达.json 每条 scenarios）

每个重大事件 2–3 个情景（如统一政府 / 分裂政府 / 结果延后），每个情景写「传导链 → 受影响标的 → 预案」，概率标【待评估】而非拍脑袋给数。预案是观察动作，不是买卖指令。

L4 历史类比（历史类比库.md）

分「市场类比」与「行为类比」。市场类比只列维度、数值标【待调权威源】；行为类比直接引用已归档事实（7-26 复盘、纪律卡、9 年收益、Hermes 检测），因为那是可直接查证的。

L5 触发与复盘（事件雷达.json 的 watch_triggers / review）

触发条件命中 → 升级为正式预警并同步到持股分析页/基金分析页；事后回填「是否提前捕捉、判断应验与否」，形成命中率统计，下一轮概率评估才有依据。

红线：本库只定义观察维度与调数口径，不填任何未经权威源核实的区间、涨跌幅或概率数字。凡涉及数值一律标【待调权威源】。

一、使用规则

  1. 每条预警事件必须挂至少一条历史类比维度；
  2. 类比先分「市场类比」与「行为类比」两层（见下），行为类比优先——因为自己的历史行为是已有档案里可直接查证的事实；
  3. 类比结论只回答「历史上出现过哪几种走法、各自持续多久、由什么信号确认」，不回答「这次会涨还是会跌」；
  4. 具体数值须调权威数据源后填写并标注来源与时点；调不到就保留【待调权威源】，不得用估算值填充；
  5. 每次事件复盘后，把「这次实际走了哪条路径」回写进对应条目，库才会越用越准。
